# Spec Editor

An in-game level editor for A2 / Orion Drift build 22284, built on the systems the build already has
rather than from scratch.

## What it is built on

The build ships a real multi-user level editor and a sandbox authoring stack; this project drives them
from a client mod instead of reimplementing them.

| Build system | What we use it for |
|---|---|
| `AALevelEditor_Minimal` — `ALevelEditorPawn` | the flying editor camera, and its **replicated** RPCs |
| `Server_AttemptLockObject(FString)` | the client→server channel (see *Transport*) |
| `Server_UnlockObject`, `Client_*Lock*` | stock multi-user object locking, unchanged |
| `ULevelEditorMinimalSubsystem` | authoritative map of who is currently editing |
| `LE_*` prefabs (`/Game/A2/Prefabs`, `/Game/A2/Progression/TimedQuest`) | the Place Actors palette |
| `SandboxEngine` (`USandboxProjectQuestData`, `USandboxQuestFile`) | quest authoring target |

## Layout

```
SpecEditor/
  mod/                  the client mod, shipped as dsound.dll
    se_core.h           thread-split spine: snapshot + command queue
    se_render.cpp       D3D12 Present hook, Dear ImGui, Unreal-styled theme
    se_ui.cpp           menu bar, Place Actors, World Outliner, Details, Quests, gizmo
    se_game.cpp         ProcessEvent pump: palette discovery, object list, command dispatch
    se_sdk_glue.cpp     the single SDK symbol we implement to avoid a 5 MB compile
    build.ps1           builds dsound.dll
  ThirdParty/imgui      Dear ImGui 1.91.5 + DX12/Win32 backends
  Install-SpecBuild.ps1 creates SpecEditorBuild/ and installs the mod
```

## Threading — the rule that keeps it from crashing

Two halves that never touch each other's data:

* **Render thread** (inside `IDXGISwapChain::Present`) draws ImGui. It may read the published snapshot
  and push commands. **It must never touch a UObject.**
* **Game thread** (inside `UObject::ProcessEvent`) owns everything UObject. It drains commands and
  republishes the snapshot.

They communicate only through `EditorState`: a mutex-guarded snapshot and a bounded command queue.

## Transport

Editor commands are tunnelled, with an `SE|` prefix, through replicated RPCs that already take a
free-form `FString`:

| RPC | When |
|---|---|
| `AVRPlayerController::Server_SetVivoxParticipantID` | **the normal path** — every client owns its controller, spectators included |
| `ALevelEditorPawn::Server_AttemptLockObject` | fallback, only while inside the game's own editor pawn |

The first version used only the editor pawn, which a player on the station is never in — so "Enter
Level Editor" could not even be sent. A real Vivox id never starts with `SE|`, so voice is untouched; and
a bare string is never sent through the Vivox RPC, where it would genuinely become your voice id.

```
SE|SPAWN|<class path>|<x,y,z>|<pitch,yaw,roll>
SE|XFORM|<Class>@<x,y,z>|<x,y,z>|<pitch,yaw,roll>|<sx,sy,sz>
SE|DELETE|<Class>@<x,y,z>
SE|QUEST|<questId>|<title>|<handle:kind,...>
SE|ENTER / SE|EXIT
```

**Actors are addressed as `Class@position`, never by name.** UE does not replicate actor names, so a
server-spawned actor carries a different name on the client, and a name sent back resolves to nothing.
Class and position are what both sides agree on. While dragging, the client addresses an object by where
it last *told* the server to put it, so a fast drag never outruns the 4 Hz snapshot.

Spawning happens on the **server**, with the actor marked replicated, which is what puts it on the wire
through Iris to every client — the whole reason commands are tunnelled rather than executed locally.

## Layout

UE5's default editor layout, docked: main menu and toolbar (`+ Add` quick-add, Start/Stop Editing in
the Play slot), **Place Actors** left, **Outliner** over **Details** right, **Content Browser** under the
viewport (folder tree + asset tiles), status bar with the Content Drawer toggle, and the viewport's own
transform toolbar top-right. Colours are UE5's stock dark palette. Window menu toggles each panel.

**All ~97 LE prefabs the game ships** are offered, not just the couple the station happens to load:
`mod\le_catalogue.txt` (generated by `tools\make_catalogue.py` from an FModel JSON export) lists them, and
the server loads a class on demand the first time one is spawned.

Content Browser: double-click a tile to place it in front of you, or **drag it into the viewport** to
place it under the cursor. `Ctrl+D` duplicates the selection.

## Mouse and keyboard

A2 hides, clips and re-centres the cursor for mouse-look. With the editor up it behaves like Unreal's
viewport instead: the cursor stays visible, `Q W E R` switch tools, typing goes into search boxes, and
`INSERT` hides the editor and gives the game everything back.

While editing, the view is a free **editor camera**: hold right mouse to look (cursor hidden and pinned),
RMB + `WASD` to fly, `E`/`Q` up/down, `Shift` 3x, wheel changes speed, `F` frames the selection.

## Viewport

The overlay projects through the camera manager's real POV (`PlayerCameraManager` →
`CameraCachePrivate.POV`: location, rotation, FOV), so the gizmo sits **on** the selected object.

* **Selecting:** click the object itself. The mouse ray is tested against each placed object's bounds
  (`GetActorBounds`, gathered on the game thread); the hovered object gets a faint box, the selection an
  orange one. Click empty space to deselect. No markers.
* **Move:** the object follows the point on the axis nearest the mouse ray, so it stays under the cursor
  at any view angle.
* **Rotate:** grab a **ring**; the angle the mouse sweeps around the centre is the angle applied, about
  the true world or local axis (composed as a rotation, not by adding to one Euler angle).
* **Scale:** proportional to how far the handle is pulled.

**Why drags are immediate.** Commands used to be handled only by the 4 Hz pump, and the local copy then
fought older replicated transforms from the server. Now the render thread writes the target into
`LiveDrag` every frame; the game thread (up to 240 Hz) moves the local actor the same frame, **holds** it
there until 1.2 s after release so stale replication cannot pull it back, and forwards it to the server at
30 Hz plus a final send on release. The command queue itself also drains every frame.

## Properties that actually take effect

Almost nothing an LE prefab exposes is replicated, and the prefabs' Luau behaviours only run for objects
the sandbox engine spawned itself — so writing a value on the server alone changes only what the server
computes. Each edit therefore:

1. is written on the server, which then runs what the engine's setter would (OnRep for RepNotify
   properties; a render-state rebuild for components — `K2_SetText` for text, a visibility toggle for
   other primitives);
2. is broadcast to every player controller through the stock reliable `APlayerController::ClientMessage`
   RPC. The mod applies it to its own copy and rebuilds it; a vanilla client only prints a console line;
3. is remembered, and replayed to an editor when they press Start Editing (actors addressed by where they
   are *now*).

**Text:** `LE_BP_Text` draws `TextRender.Text` (an `FText`). Editing the Luau `Text.Text` string mirrors
into it. String/text values are built by the engine (`Concat_StrStr`, `Conv_StringToText`) and the
property takes ownership; the old value is leaked, never freed from outside the engine's allocator.

**Limit:** players on an unmodded client (Quest) see only what the server computes and replicates —
gameplay values the server evaluates, transforms, spawns and deletes — not client-drawn values such as
text or colours.

## Testing without a human

```powershell
# server (background it -- it waits minutes for the engine)
.\HalcyonA2\tools\Start-Server.ps1 -Config server.specedit.psd1
# client: joins by itself and runs the script through the same queue the UI uses
A2-Win64-Shipping.exe -windowed -nohmd -SpecEditConnect=127.0.0.1:7777 -SpecEditScript=SpecEditor\tests\e2e.txt
```

`-SpecEditConnect` exists because the spectator build has no auto-connect of its own. The script logs
`[script] PASS/FAIL` and `[repl]` lines (what this client can see) to `%TEMP%\spec_editor.log`; the
server logs `[SPECEDIT]` lines. `-SpecEditLocalTest` on the server admits org-less callers, because a
no-auth local server has no dashboard — **local only**.

## Build and install

`ThirdParty/imgui` is a clone and is **not tracked** (it carries its own `.git`). Fetch it once:

```powershell
git clone --branch v1.91.5 --depth 1 https://github.com/ocornut/imgui ThirdParty\imgui
```

```powershell
.\mod\build.ps1                 # -> mod\dsound.dll
.\Install-SpecBuild.ps1         # -> ..\SpecEditorBuild with the mod installed
.\Install-SpecBuild.ps1 -ModOnly  # refresh just the DLL after a rebuild
```

`Install-SpecBuild.ps1` hard-links the source build by default, so a full editor build costs seconds
and almost no disk. It also copies `LibOVRP2P64_1.dll` / `LibOVRPlatformImpl64_1.dll` if the source
build lacks them — `specnovbuild` does, and without them the client exits during start-up in a way that
looks exactly like "the mod broke the game".

Launch, then **INSERT** toggles the UI. Log: `%TEMP%\spec_editor.log`.

Controls: `Q` select, `W` move, `E` rotate, `R` scale, `Esc` deselect, `Del` delete. Drag a gizmo axis
handle to transform; snapping is configurable in Details.

## Status

**Working end to end on a local server** (tests below). Client: UE5-style overlay, 97-prefab palette,
editor camera, click-to-select, gizmo with live drag channel, Details with editable properties (numbers,
enums, names, vectors, colours, strings, text), quest authoring. Server: fenced dispatch (`-SpecEdit`,
allowlist, LE_-only, rate cap), spawn with replication, move/rotate/scale/delete, property writes with
refresh + broadcast + replay, authored quests delivered on join.

Test scripts (`tests\`): `e2e.txt` (spawn/replicate/move/delete), `props.txt` (red-coin Duration),
`full.txt` (text edited locally, from the server, via the Luau mirror; font size; two drags through
LiveDrag), `ui.txt` (paired with an external mouse driver: click-select, handle drag, ring rotate).

Not yet proven: a newly published quest reaching players already on the station without rejoining, and
quest steps counting progress.
